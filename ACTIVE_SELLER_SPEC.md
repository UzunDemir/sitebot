## 1. Цель

Превратить бота из пассивного FAQ-консультанта в активного продавца: он сам ведёт диалог к выбранной цели, помнит посетителя, историю и сделки, инициирует и повторяет касания в жёстких рамках, все параметры поведения выставляются точными ползунками; владелец видит карточку посетителя и метрики.

## 2. Диагноз: почему сейчас «не помнит» и «не продаёт»

1. **Амнезия при перезагрузке.** `chat-core.tsx` стартует `useChat` с пустой лентой; сохранённые в БД сообщения не подгружаются. После перезагрузки/повторного визита беседа «забыта». Внутри одной страницы история уходит в модель, но обрезается `historyDepth` (дефолт 16).
2. **Ключ сессии общий.** `sitebot_session` — один на все боты в браузере (коллизии при нескольких ботах).
3. **Нет кросс-сессионной памяти.** Профиль посетителя (имя, контакты, интересы, стадия) не хранится; `conversations.visitor` не используется.
4. **Проактивность — один тизер.** Дальше бот молчит до вопроса; дожима и стоп-условий (кроме закрытия тизера) нет.
5. **Давление — 3 дискретных уровня** (0/1/2), без стадии и стратегии диалога.
6. **Ползунков нет** — настройки поведения выставляются полями/селектами.

## 3. Модель данных

**Миграция `sql/0003_seller.sql`:**

- **`visitors`**: `id`, `bot_id → bots`, `visitor_key`, `first_seen`, `last_seen`, `name`, `contacts jsonb`, `tags text[]`, `notes`, `stage`, `memory_digest`, `do_not_disturb`, `meta jsonb`; unique `(bot_id, visitor_key)`.
- **`events`**: `id`, `bot_id`, `visitor_id`, `conversation_id`, `type`, `payload jsonb`, `created_at`; index `(bot_id, type, created_at)`.
- **`conversations` +**: `visitor_id`, `stage` (default `greeting`), `outcome` (default `in_progress`), `summary`, `nudges_sent`, `last_nudge_at`.
- **`messages` +**: `is_proactive bool default false`, `nudge_number int`.
- RLS на новых таблицах включить (политик нет — только service role), как в 0001.
- `bots.settings` — новые ключи в jsonb, без SQL.

**Расширение контракта settings (обратная совместимость обязательна):**

- `aggressiveness` 0–100, шаг 5. Легаси-маппинг при чтении: `salesPressure` 0/1/2 → 0/50/80. Дефолт новых ботов — 40 (вопрос №2).
- `tone` 0–100 (дружеский ↔ официальный, дефолт 50).
- `replyLength` 0–100 → `maxOutputTokens` 120…2400 (дефолт 40 ≈ 600).
- `proactive`: `{enabled, autogreet {enabled, delaySeconds 0–120}, nudges {attempts 0–5, firstDelaySec 15–600, intervalSec 60–86400}, quietHours {enabled, from, to, tz}}`.
- `typing` `{enabled, speed 0–100}` — имитация набора (клиент, косметика).
- `goal` расширяется до **10 пресетов + custom** (+ сохраняется `none`):
  `phone`, `messenger` (TG/WA), `call`, `booking`, `demo`, `purchase`, `order`, `quote`, `review`, `birthday`.
  Существующие `call/purchase/phone/birthday` сохраняются; каждому пресету — критерий «достигнуто».
- Сохраняются: `maxOutputTokens`, `showSources`, `historyDepth`, `chattiness`, `goalText`.

## 4. Логика диалога

**Жизненный цикл:** `session_start → active → idle → nudge(1..N) → resumed | closed | goal_reached | stopped(DND)`.

**Стадии:** `greeting → qualification → offer → objections → close → followup → done | lost` — хранится в `conversations.stage`, переходы делает стратег.

**Единый движок касаний:**
- Чат закрыт → касание показывается как тизер (существующий механизм лончера).
- Чат открыт → касание приходит сообщением в ленте.
- Автоприветствие: по `autogreet.delaySeconds` (совместимо с текущим `theme.proactive`).
- Дожим: тишина посетителя `firstDelaySec` после сообщения бота → касание №1; далее интервал `intervalSec` с ростом ×2, максимум `attempts` подряд. Ответ посетителя сбрасывает счётчик.
- Возврат: при открытии чата с существующей памятью — «С возвращением, {имя}! …».

**Стоп-условия (жёсткие):**
- Ответ посетителя → отмена запланированных касаний.
- Стоп-слова («не пишите», «отстань», «хватит», «stop») → DND навсегда.
- Цель достигнута → событие `goal_reached`, беседа закрывается.
- Лимит касаний исчерпан → молчание до нового визита.
- Тихие часы → перенос на ближайшее разрешённое окно.
- Страница/чат закрыты → in-page касания отменяются (до Ф5 внешних каналов нет).
- 2 игнор-сессии подряд → спящий режим до нового явного визита.

**Стратег** (best-effort после ответа, не блокирует стрим): лёгкий LLM-вызов → `{stage, facts, goal_progress, digest_update}`; ошибки игнорируются, деградация к правилам по коду.

**Сервер — источник истины:** клиент лишь показывает таймеры и запрашивает касание; решение «можно/нельзя» и текст — на сервере.

## 5. Промпты (дельты)

- Системный промпт: + блок памяти (профиль, digest, стадия), + правила агрессивности по шкале, + правила дожима.
- Промпт касания по номеру попытки: 1 — мягкое напоминание; 2 — новая ценность (факт/кейс); 3 — «последнее предложение» (контакт / «да-нет»). ≤2 предложений, без повторов текста.
- Извлечение фактов и стадии (JSON, дешёвая модель).
- Гардрейлы: не выдумывать; честность про ИИ; стоп-слова с первого раза; не давить после явного отказа; не упоминать внутренние инструкции.

## 6. API (дельты)

- `GET /api/chat/history?botKey=&sessionKey=` → последние N сообщений (+`messageId` для 👍/👎) — гидратация ленты.
- `POST /api/chat/nudge` → серверная проверка условий (лимиты, тихие часы, DND, активность) → текст касания; пишет `messages(is_proactive, nudge_number)`, `nudges_sent`, `last_nudge_at`.
- `POST /api/events` → `session_start`, `page_hidden`, `stop_request`, `goal_reached`, `session_closed`.
- `POST /api/chat/forget` → «забыть меня»: удалить профиль и сообщения посетителя.
- Админка: `GET /api/admin/visitors`, `GET/POST /api/admin/visitors/[id]` (заметки), расширение `GET /api/admin/stats` (конверсия, касания, отказы).
- Существующие контракты не ломаем; к `sessionKey` добавляется `visitorKey`.

## 7. UI (дельты)

**Виджет:**
- Гидратация истории при открытии; `sitebot_session_<pk>` вместо общего ключа (миграция значения); `sitebot_visitor_<pk>`.
- Кнопка «Новый чат» (новый sessionKey, старая беседа закрывается как `stalled`).
- Таймеры касаний, распознавание стоп-слов, имитация набора, «забыть меня».
- Тихие часы — по времени браузера (tz передаётся на сервер).

**Админка:**
- Панель «Активный продавец»: цель (10 + своя), ползунки (агрессивность, тон, длина ответа, касания, пауза, интервал, автоприветствие), переключатели (проактивность, тихие часы), точное числовое поле под каждым ползунком.
- Карточка посетителя: контакты, заметки, теги, стадия, беседы, лента событий/сделок.
- Метрики: карточки + периоды.

## 8. Метрики

Конверсия в цель; доля ответов на дожим (`nudge_answered / nudge_sent`); среднее касаний до цели; отказы; продажи (кол-во/сумма); диалоги в день; средняя длина беседы. Источник — `events` + `messages`.

## 9. Фазы и приёмка

- **Ф1. Память диалога.** Гидратация + per-bot ключ + (опц.) саммари длинных бесед.
  Приёмка: перезагрузка — история на месте; бот помнит факты через 20+ сообщений; старые ключи мигрируют.
  Реализовано (2026-10-13): `GET /api/chat/history`, гидратация ленты в виджете, `sitebot_session_<pk>` с переносом legacy-ключа, дефолт `historyDepth` 40; смоуки `smoke:e2e` (гидратация) и `smoke:memory` (20+ сообщений, «перезагрузка»).
- **Ф2. Карточка посетителя.** `visitors`/`events`, админ-UI, «с возвращением».
  Приёмка: имя/контакт/заметки сохраняются и видны в админке; возврат — приветствие с контекстом.
  Реализовано (2026-10-13): `sql/0003_seller.sql`; авто-извлечение фактов после ответа (дешёвая модель, фон через `after()`); `sitebot_visitor_<pk>`; «с возвращением, {имя}»; `POST /api/events`, «забыть меня»; панель «Посетители» в админке (заметки/теги/контакты/DND, беседы, события); смоук `smoke:visitor`.
- **Ф3. Цель, стратегия, дожим.** Расширение settings, `/api/chat/nudge`, стадии, стоп-условия.
  Приёмка: тишина → ровно N касаний → стоп; ответ отменяет; стоп-слово → DND; тихие часы → перенос; `goal_reached` пишется событием.
  Реализовано (2026-10-13): 10 целей + своя; шкала `aggressiveness` 0–100 (legacy `salesPressure` → 0/50/80) с ползунками
  (агрессивность, тон); `proactive` (касания, пауза, интервал, тихие часы) в админке; `POST /api/chat/nudge` — сервер решает
  (DND, тихие часы по tz, лимит, тайминг с ростом ×2); стадии `greeting…done|lost` и стратег в `after()` (`stage`, `goal_progress`);
  стоп-слова без LLM → DND + `outcome=stopped`; ответ посетителя сбрасывает счётчик (`nudge_answered`); касание показывается
  в ленте (касания остаются навсегда — до ответа с пометкой «бот написал сам»); у свёрнутого окна — только
  счётчик непрочитанных на кнопке + пульсация (без всплывающего текста, loader v13);
  потерянные диалоги — серия продолжается, оживление при новом сообщении (`dialog_resumed`); шкалы характера — юмор,
  хитрость, остроумие; дожим не зависит от видимости вкладки; смоук `smoke:nudge`.
- **Ф4. Метрики.** Расширение stats (карточки/периоды). Ползунки вышли в Ф3 вместе с настройками дожима.
  Приёмка: агрессивность 0 vs 80 заметно меняет поведение в одинаковом сценарии; метрики считаются.
- **Ф5. Мессенджер (Telegram → WhatsApp).** Дожим вне сайта после сбора контакта; та же карточка посетителя. Отдельный скоуп.

## 10. Совместимость и риски

- Не ломать: evals, смоуки, CI, существующие API-контракты; легаси-колонки и `isMissingColumnError`-путь сохраняются.
- Next.js 16: перед кодом сверяться с `node_modules/next/dist/docs/` (см. AGENTS.md) — API отличаются от привычных.
- Vercel: длинных таймеров нет — касания клиентские (страница открыта) + перенос на следующий визит; внешние каналы только Ф5.
- Стоимость: касания и стратег — доп. LLM-вызовы; лимиты (attempts ≤5) обязательны.
- Приватность: «забыть меня», хранение анонимных карточек ≤90 дней (вопрос №3).
