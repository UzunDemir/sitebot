# sitebot — как всё устроено

Полное описание проекта: структура, файлы, потоки данных, логика, настройка личности бота
и память. Документ рассчитан и на владельца продукта, и на разработчика, который заходит в
код впервые.

- **Что это:** встраиваемый чат-ассистент по базе знаний (RAG) с поведением «активного
  продавца»: сам ведёт диалог к цели, помнит посетителя между визитами, дожимает молчунов,
  все параметры поведения настраиваются без кода — из админки.
- **Прод:** https://sitebot-nu.vercel.app · админка: `/admin` (пароль = `ADMIN_SECRET`).
- **Репозиторий:** https://github.com/UzunDemir/sitebot (ветка `main`).
- **Связанные документы:** `README.md` (быстрый старт), `DEPLOY.md` (деплой), `RUNBOOK.md`
  (эксплуатация и частые проблемы), `ACTIVE_SELLER_SPEC.md` (ТЗ инициативы «Активный
  продавец», фазы Ф1–Ф5).

## 1. Стек

| Слой | Технология |
|---|---|
| Фронтенд/сервер | Next.js 16.4 (App Router, TypeScript strict, React 19.3, Tailwind 4, Turbopack, `cacheComponents`) |
| LLM | DeepSeek через Vercel AI SDK 7 (`@ai-sdk/deepseek`), стриминг UI-сообщений |
| RAG-хранилище | Supabase Postgres + pgvector (HNSW, cosine) + FTS `russian` (GIN) |
| Эмбеддинги | Google Gemini `gemini-embedding-001`, 1536 измерений (MRL), бесплатный tier |
| PDF | `unpdf` (извлечение текста на сервере) |
| Хостинг | Vercel (прод), GitHub Actions (CI) |

Доступ к базе — **только с сервера** (service-role ключ). Браузер в Supabase не ходит:
все данные проходят через Next.js API. RLS включён на всех таблицах без анонимных политик —
это жёсткая страховка, а не основной механизм доступа.

## 3. Два способа увидеть бота

**1. Страница сайта** (`/`): `app/chat.tsx` тянет `GET /api/bot`, показывает переключатель
ботов (если их несколько), рендерит `<Chat>` и сниппет вставки. Тут же удобно тестировать
ответы и оформление.

**2. Виджет на чужом сайте:** владелец вставляет одну строку:

```html
<script src="https://sitebot-nu.vercel.app/loader.js?v=14" data-bot="pk_..." async></script>
```

`loader.js` создаёт кнопку-пузырь, а сам чат живёт в iframe со страницы
`/embed/<public_key>`. Общение loader ↔ чат — через `postMessage`.

### 3.1. Протокол postMessage

Чат (iframe) → loader:

- `sitebot:minimize` — свернуть окно (кнопка «▾» в шапке);
- `sitebot:move` / `sitebot:move-reset` — перетаскивание окна за шапку;
- `sitebot:unread {count}` — сколько непрочитанных касаний накопилось (свёрнутое окно);
- `sitebot:nudge {text}` — текст касания (отправляется, loader'ом не используется — резерв).

Loader → чат (iframe):

- `sitebot:chat-opened` / `sitebot:chat-closed` — окно открыто/свёрнуто (чат ведёт счётчик
  непрочитанных и останавливает пульсацию).

### 3.2. Что умеет loader.js (v14)

- читает `data-*`-атрибуты (`data-color`, `data-icon`, `data-position`, `data-width`,
  `data-height`, `data-label`) и тему бота через `GET /api/bot?key=`;
- круглая кнопка (48–80 px) с эмодзи/картинкой/подписью, перетаскиваемая мышью и пальцем
  (позиция запоминается на время открытой страницы);
- анимация появления (fade/slide/pop), тень, прозрачность — всё из темы;
- **тизер** (`theme.proactive`): всплывающий текст возле кнопки через N секунд после
  загрузки; закрытие запоминается в `localStorage` (`sitebot_teaser_<pk>`);
- **счётчик непрочитанных + пульсация**: когда окно свёрнуто и пришло касание-дожим,
  на кнопке появляется красный счётчик, кнопка и счётчик пульсируют, а вокруг кнопки
  расходится кольцо. Реализовано на Web Animations API (`Element.animate`) — работает
  независимо от системных настроек «уменьшить движение» и от CSP-блокировок стилей.
  Открытие чата останавливает анимацию и сбрасывает счётчик;
- версия видна в консоли: `[sitebot] loader v14 · bot pk_…` (и в `window.__sitebotLoader`);
- кэш файла: `max-age=300, stale-while-revalidate=86400` (см. `next.config.ts`), поэтому
  сниппет с `?v=14` ускоряет доставку обновлений.

Версии: v10 — база (тема/драг/тизер), v11 — дожим-тизер, v12 — счётчик непрочитанных,
v13 — «только счётчик + пульсация», v14 — пульсация/кольцо на WAAPI.

## 4. Пайплайн сообщения: `POST /api/chat`

Это сердце системы. Пошагово (актуальный код — `app/api/chat/route.ts`):

1. **Разбор тела:** `{ messages, botKey, sessionKey, visitorKey }`. Клиент присылает свои
   видимые сообщения — они используются только для двух вещей: взять текст последней
   реплики и (запасной путь) восстановить контекст, если `sessionKey` нет.
2. **Резолв бота** по `public_key` (+ `is_active`), чтение `bots.settings` с деградацией,
   если миграция 0002 не применена (`isMissingColumnError` → старые колонки).
3. **Дневная квота**: `quota_counters` — максимум **300 запросов на бота в сутки**
   (UTC-день). При превышении — 429 с понятным сообщением. Учёт токенов — там же.
4. **Текст запроса** — последняя реплика пользователя (нужна для поиска и стоп-слов).
5. **Окно памяти** `historyDepth` (дефолт 40 сообщений; 0 = вся беседа, cap 200).
6. **Персистенция (best effort):** `ensureConversation(bot, sessionKey)` +
   `saveUserMessage`. Даже если запись не удалась — чат продолжит работать.
7. **Карточка посетителя (best effort):** `ensureVisitorRow(bot, visitorKey)` +
   привязка беседы к карточке (`conversations.visitor_id`). Без миграции 0003 — просто
   пропускается.
8. **Состояние беседы:** `stage/outcome/nudges_sent` из `conversations`.
9. **«Ответ отменяет дожим»:** если `nudges_sent > 0` → событие `nudge_answered` и сброс
   счётчика. Если беседа была `lost` или уже достигла цели (`goal_reached`) — она **оживает**
   (`outcome = in_progress`; цель можно достичь заново) + событие `dialog_resumed`.
   «Стоп-слово» (`stopped`) и DND не оживают.
10. **Стоп-слова** («не пишите», «отстань», «хватит», «stop» и др., `lib/nudge.ts`):
    посетитель получает вежливый canned-ответ **без вызова LLM и без поиска**, карточке
    ставится `do_not_disturb = true`, беседе — `outcome = stopped`, пишется событие
    `stop_request`. С этого момента дожим молчит навсегда.
11. **Поиск по базе знаний** (`hybridSearch`, см. §5) — вектор + FTS, слияние RRF.
12. **Сборка промпта** (`buildSystemPrompt`): системный промпт бота + директивы личности
    (общительность, цель, агрессивность, тон, юмор/хитрость/остроумие) + **блок памяти**
    посетителя (имя, контакты, интересы, заметки, стадия) + правила цитирования и фрагменты
    базы знаний `[n]`.
13. **Контекст модели — из базы, а не из браузера.** Сервер сам читает последние
    `historyDepth` сообщений беседы (включая только что сохранённую реплику) и строит
    `messages` для модели. Именно поэтому виджет может показывать чистую ленту без истории,
    а бот — всё помнить.
14. **Генерация:** `streamText` (DeepSeek; температура по настройке, при включённом
    «reasoning» — игнорируется; `maxOutputTokens` из настроек; thinking выключен по
    умолчанию).
15. **Стрим UI-сообщений:**
    - `data-sources` — источники `[n]` для чипов под ответом (если `showSources`);
    - текст ответа;
    - после завершения: сохранение ответа в `messages` (с цитатами, токенами, оценкой
      стоимости), выдача `data-feedback` (id сообщения для 👍/👎), доучёт токенов в квоту.
16. **Фоновый стратег (`after()`)**: после отдачи ответа запускается дешёвый LLM-вызов,
    который обновляет карточку посетителя, стадию диалога и состояние цели (см. §9).
    Пользователь его не ждёт.

## 5. RAG: поиск и индексация

### 5.1. Гибридный поиск (`lib/retrieval.ts`)

- **Векторная ветка:** `match_chunks` — косинусная близость по HNSW-индексу `chunks.embedding`
  (1536 dims), 8 кандидатов.
- **Лексическая ветка:** `search_chunks_fts` — полнотекстовый поиск `to_tsvector('russian')`
  + `websearch_to_tsquery`, 8 кандидатов. Падение FTS не критично — векторная ветка ответит.
- **Слияние RRF** (Reciprocal Rank Fusion, k=60): `1/(60 + позиция)` от каждой ветки,
  сумма → топ `top_k` (1–10, дефолт 6).
- К чанкам подтягиваются `title`/`source` документов — для цитат.

### 5.2. Индексация (`lib/ingest.ts`, `lib/chunker.ts`, `lib/embeddings.ts`)

- **Чанкер:** структурный — по абзацам, мягкий лимит 1200 символов, перекрытие 150.
- **Эмбеддинги:** Gemini `gemini-embedding-001` (MRL → 1536), батчами по 24 с паузой 10 с
  (бесплатный tier считает каждый текст за запрос). Ретраи по подсказке провайдера
  («Please retry in Xs», ≤60 с). Если ждать дольше бюджета — `BudgetExceededError`.
- **Пайплайн:** `pending → processing → ready | error`. Большие документы обрабатываются
  **частями**: за один вызов сервер работает ≤45 с (лимит Vercel 60 с), сохраняет прогресс
  и возвращает `partial`; админка сама дёргает `POST /api/admin/documents/[id]` раундами
  (до 10), пока не будет `ready`. Повторный вызов **продолжает** с уже вложенных чанков
  (защита по `content_hash` + набор `idx`) — заново ничего не эмбеддится.
- Лимиты: текст ≤300 000 символов, файл ≤4 МБ, форматы `.txt/.md/.markdown/.pdf`
  (PDF — `unpdf`, извлечение на сервере).
- Ошибка квоты Google превращается в понятный текст: «прогресс сохранён, подождите
  минуту-две и нажмите „повторить“».
- Смена модели эмбеддингов = полная переиндексация (обновить `vector(N)` в SQL и пересидить).

Полная схема — в `sql/0001_init.sql`, `sql/0002_settings.sql`, `sql/0003_seller.sql`.

## 7. Настройки бота: `bots.settings`

Хранятся одной jsonb-колонкой (`0002`). Единая точка правды — `lib/bot-settings.ts`:
типы, дефолты (`BOT_SETTINGS_DEFAULTS`), санитайзер `parseBotSettings` (клампит диапазоны,
отбрасывает мусор) и производные: `effectiveAggressiveness`, `effectiveProactive`.

| Поле | Тип/диапазон | Дефолт | Что делает |
|---|---|---|---|
| `maxOutputTokens` | 120–2400 | 600 | Ограничение длины ответа |
| `showSources` | bool | true | Показывать чипы источников и маркеры `[n]` |
| `historyDepth` | 0–50 | 40 | Сколько последних сообщений беседы видит модель (0 = вся, cap 200) |
| `chattiness` | strict / friendly / proactive / initiator | friendly | Стиль общения (директивы в промпт) |
| `goal` | 10 пресетов + custom | none | Цель диалога (см. §8.2) |
| `goalText` | строка ≤200 | — | Своя цель для `custom` |
| `aggressiveness` | 0–100 (шаг 5) | 40 | Напор продаж, 4 уровня директив |
| `salesPressure` | 0/1/2 (legacy) | — | Старая настройка; маппится в 0/50/80, если `aggressiveness` не задан |
| `tone` | 0–100 | 50 | Тон: 0 дружеский ↔ 100 официальный |
| `humor` | 0–100 | 30 | Юмор (запрет шутить над клиентом) |
| `cunning` | 0–100 | 40 | Хитрость убеждения (обман запрещён) |
| `wit` | 0–100 | 30 | Остроумие формулировок |
| `proactive.enabled` | bool | true | Разрешить касания-дожим |
| `proactive.nudges.attempts` | 0–5 | 2 | Максимум касаний подряд |
| `proactive.nudges.firstDelaySec` | 15–600 | 45 | Пауза молчания перед касанием №1 |
| `proactive.nudges.intervalSec` | 60–86400 | 300 | Пауза перед касанием №2 (дальше ×2: 2×, 4×…) |
| `proactive.quietHours` | `{enabled, from, to}` | выкл, 21:00–09:00 | Не писать в это время (по tz посетителя) |

Соседние слои того же бота: `system_prompt` (характер и роль, задаёт владелец),
`greeting` (первый пузырь в чате), `theme` (внешний вид виджета — `lib/widget-theme.ts`),
`allowed_origins` (где разрешено встраивание).

## 8. Личность бота: как это запрограммировано

Личность — комбинация трёх слоёв: **кто бот** (`system_prompt`), **как себя ведёт**
(`settings`) и **как выглядит** (`theme`). Слои `system_prompt` и `settings` не
подменяют друг друга: первый отвечает на «кто ты и что знаешь», второй — на «насколько
активно, тепло, настойчиво». Собранная «личность» на каждый запрос превращается в системный
промпт функцией `buildSystemPrompt` (`lib/prompts.ts`).

### 8.1. Порядок блоков промпта

1. `system_prompt` бота (свой текст владельца);
2. стиль общения (`chattiness`) — одна из 4 директив;
3. цель диалога (`goal` / `goalText`) — формулировка «Цель диалога: …»;
4. агрессивность продаж — одна из 4 директив с **жёсткими гардрейлами**;
5. тон (`tone`) — появляется только на краях шкалы (≤30 дружеский, ≥70 официальный);
6. **шкалы характера** (`humor`, `cunning`, `wit`) — по одной директиве на шкалу;
7. блок памяти посетителя (имя/контакты/интересы/заметки/стадия);
8. правила контекста: «отвечай только по фрагментам базы знаний», честный отказ, цитаты
   `[n]` (или запрет цитат при `showSources=false`), язык пользователя, без markdown;
9. сами фрагменты базы знаний с номерами.

### 8.2. Шкалы: что именно уходит в промпт

Каждая шкала разбита на «полосы» — так владелец получает предсказуемое изменение поведения
от ползунка, а модель — однозначную формулировку:

- **Общительность** (`chattiness`): «строго по вопросу» / «дружелюбно + один уточняющий
  вопрос» / «проактивно: варианты и следующий шаг» / «ведёт диалог: по одному вопросу за
  сообщение».
- **Агрессивность** 0–20 «без давления» → 21–45 «мягко предложить один вариант» →
  46–70 «в каждом ответе один шаг к цели» → 71–100 «активно вести к цели» + явные
  ограничения: не давить после двух отказов, не выдумывать скидки и выгоды, не
  манипулировать. Legacy `salesPressure` маппится в 0/50/80.
- **Тон**: ≥70 — «официальный, „вы“, без сленга и эмодзи»; ≤30 — «дружеский, тёплый,
  без панибратства»; середина — без директивы.
- **Юмор**: ≤20 «без шуток» → 21–60 «лёгкая уместная шутка» → 61–100 «шути активно», но
  никогда над клиентом, его проблемой или деньгами.
- **Хитрость**: ≤20 «говори прямо» → 21–60 «мягкие приёмы: интрига, встречный вопрос,
  акцент на выгоде» → 61–100 «вместо „нет“ — альтернатива», при этом честность
  неприкосновенна: никаких выдуманных скидок и дефицита.
- **Остроумие**: ≤20 «простые формулировки» → 21–60 «живые, меткие» → 61–100 «остроумно
  и неожиданно, но по делу и понятно».

**Цель диалога** — 10 пресетов + своя: `phone` (телефон), `messenger` (перевести в
Telegram/WhatsApp), `call` (договориться о звонке), `booking` (визит/примерка), `demo`,
`purchase`, `order`, `quote` (расчёт), `review` (отзыв), `birthday` (дата рождения).
Каждой цели соответствует строка-директива для ответов и короткая формулировка для
промпта касания («Цель диалога: получить телефон посетителя»). Достижение цели определяет
стратег (см. §9.2): для `phone`/`call` — по появлению телефона в контактах, для `messenger` —
по Telegram/WhatsApp, остальные — по вердикту модели (`goal_progress: achieved`).

### 8.3. Как это редактируется в админке

Вкладка **«Логика»** карточки бота:

- базовое: название, модель, приветствие, `top_k`, reasoning-режим, «Бот активен»;
- «Поведение»: размер ответа (с подсказкой «≈ N знаков»), память диалога, общительность
  (селект), **ползунки**: агрессивность / тон / юмор / хитрость / остроумие — все 0–100
  с шагом 5 и живым значением рядом с подписью; цель (селект 12 пунктов + «Своя цель…»
  с текстовым полем); переключатель источников (с предупреждением, что проверяемость
  пострадает);
- «Дожим молчащих посетителей»: включён/выключен, касаний подряд (0–5), пауза перед
  первым (15–600 с), интервал между касаниями (60–86400 с; рост ×2 применяется в движке),
  тихие часы с/до (time-поля, по местному времени посетителя);
- системный промпт (текстовое поле).

Под ползунком агрессивности есть подсказка для старых ботов: если у бота осталась только
`salesPressure`, показано «действует старая настройка…» — достаточно тронуть ползунок,
чтобы закрепить новую шкалу.

Сохранение идёт `PATCH /api/admin/bots/[id]`, где `parseBotSettings` ещё раз санитизирует
значения — мусор из запроса не попадает в базу. Если миграция 0002 не применена, API честно
отвечает `settings_not_migrated` с инструкцией.

## 9. Память бота: как это устроено

Память живёт на **сервере**, в базе; виджет её не воспроизводит. Три слоя памяти:

### 9.1. Память диалога (беседа)

- Ключ сессии — `sitebot_session_<public_key>` в localStorage: у каждого бота своя беседа.
  Старый общий ключ `sitebot_session` (до апгрейда) **мигрирует**: если у посетителя есть
  только он, значение переносится в per-bot ключ — старая беседа не теряется.
- Беседа — строка в `conversations` (уникальность `bot_id + session_key`), реплики —
  в `messages`.
- **Контекст модели собирается сервером из БД** — последние `historyDepth` сообщений
  (0 = вся беседа, с sanity-cap 200). Клиентский массив сообщений при наличии `sessionKey`
  игнорируется (берётся только текст последней реплики). Поэтому перезагрузка страницы,
  новая вкладка или возврат через неделю ничего не «ломают»: бот отвечает так, будто
  беседа не прерывалась.
- **Лента виджета всегда чистая** — прошлая переписка не выводится (сознательное решение
  по итогам эксплуатации: «история в памяти, не на экране»). Максимум, что видит посетитель
  из «прошлого», — приветствие «С возвращением, {имя}!». Нужна техническая история
  (для отладки/смоуков) — `GET /api/chat/history` отдаёт её как UI-сообщения.

### 9.2. Карточка посетителя

- Стабильный идентификатор — `sitebot_visitor_<public_key>` (не ротируется, в отличие от
  сессии). Карточка — строка в `visitors`: имя, контакты (`phone/email/telegram/whatsapp/
  vk/instagram/other`), теги, заметки владельца, `memory_digest`, `do_not_disturb`, интересы
  в `meta`, метки первого/последнего визита.
- **Стратег** (`lib/visitor-memory.ts`, `runStrategist`) запускается из `after()` после
  каждого ответа: берёт хвост диалога (последние 12 сообщений) + текущую карточку, делает
  один дешёвый LLM-вызов (DeepSeek flash, JSON) и возвращает:
  - факты (`name`, `contacts`, `interests`, `note`) — для карточки;
  - `stage` — стадия диалога: `greeting → qualification → offer → objections → close →
    followup → done | lost`;
  - `goal_progress` — `none | progress | achieved`.
- **Санитайз и слияние:** все значения обрезаются по длинам, контакты — только из белого
  списка ключей; имя и контакты владельца **не перезаписываются** (`mergeVisitorFacts`),
  интересы объединяются, `note` попадает в `memory_digest`.
- **Дедупликация дайджеста:** похожие записи не копятся — перед добавлением новая заметка
  сравнивается со старыми (вложение строк или совпадение слов Jaccard ≥ 0.5); при сходстве
  запись **заменяется** свежей формулировкой. Дайджест ограничен 14 строками / ~1800
  символами. Стратегу также запрещено писать в заметки рассуждения о самом ассистенте
  («документация», «пытается дожать») — это не факт о посетителе.
- **Достижение цели:** если цель `phone`/`call` и в контактах появился телефон — беседа
  закрывается как `goal_reached` (+ событие) независимо от вердикта модели; аналогично
  `messenger` для Telegram/WhatsApp. Иначе используется `goal_progress: achieved`.
- `lost` ставится **только при явном отказе** продолжать (не при паузах и шутках) —
  и не является «глухим стопом»: см. §9.4.

### 9.3. События (воронка)

`events` пишет то, чего не видно в сообщениях:

| Тип | Кто и когда |
|---|---|
| `session_start` | виджет, один раз за загрузку страницы |
| `page_hidden` | виджет, при уходе со страницы (троттлинг 1/60 с, чтобы не спамить) |
| `stop_request` | сервер, при стоп-слове |
| `nudge_sent` | сервер, при каждом касании (payload: номер, агрессивность, реактивация) |
| `nudge_answered` | сервер, если посетитель ответил после дожима (payload: сколько касаний «сгорело») |
| `dialog_resumed` | сервер, когда посетитель оживил беседу из `lost` или достигнутой цели (`goal_reached`) |
| `goal_reached` | сервер, при достижении цели (payload: goal) |

### 9.4. Дожим молчунов (движок касаний)

Две половины:

- **Клиент** (`chat-core.tsx`) — таймер-цикл: раз в ~20 с «тик» спрашивает сервер, можно ли
  касание; живёт на нормальных таймерах, **не** зависит от видимости вкладки (свёрнутая
  вкладка — касание всё равно придёт), останавливается только на терминальных состояниях
  (`goal_reached`, `stopped`, `do_not_disturb`, выключено). Полученный текст показывается
  в ленте с пометкой «Бот написал сам»; при свёрнутом окне — счётчик + пульсация на кнопке.
- **Сервер** (`POST /api/chat/nudge`) — единственный, кто решает «можно/нельзя»:
  1. `proactive.enabled` и `attempts > 0` → иначе `disabled`;
  2. беседа существует → `no_dialog`;
  3. глухие стопы (`goal_reached`, `stopped`, `stage=done`) → `closed`;
  4. беседа `lost` → это **реактивация**: касание разрешено, текст генерируется как
     «последнее предложение»; серия продолжается по общему лимиту, пока посетитель не ответит;
  5. `do_not_disturb` карточки → `dnd`;
  6. тихие часы в tz посетителя → `quiet_hours` + `nextAllowedAt`;
  7. лимит касаний исчерпан → `limit`;
  8. тайминг: тишина с последнего сообщения/касания ≥ `firstDelaySec` (для первого) или
     `intervalSec × 2^(n-1)` (для последующих) → иначе `too_early` + `retryAfterMs`;
  9. всё ок — генерация текста (дешёвая модель; правила различают касание №1 «мягко
     напомни», №2 «добавь ценность», №3 «последнее предложение»; фолбэк — canned-текст),
     запись в `messages` как `is_proactive=true` с номером, обновление счётчиков
     (`nudges_sent`, `last_nudge_at`, `stage=followup`) и событие `nudge_sent`.

Ответ посетителя сбрасывает серию (`nudge_answered` + `nudges_sent=0`) — счётчик начинается
заново, следующий цикл будет снова с «паузы первого касания».

### 9.5. Приветствие и «Забыть меня»

- **«С возвращением»**: виджет делает лёгкий запрос `GET /api/chat/history?...&limit=1`,
  получает `visitor: {name, returning}` и показывает «С возвращением, {имя}!» вместо
  стандартного приветствия. Этот же запрос забирает конфиг дожима и состояние беседы.
- **«Забыть меня»** (ссылка под полем ввода, двухшаговая): `POST /api/chat/forget`
  не удаляет данные — ставит маркер эпохи (`memory_resets`, `sql/0005_memory_reset.sql`):
  активная память (имя, контакты, дайджест, ДР, предпочтения, претензии, интересы)
  обнуляется, контекст модели, дожим и покупки видят только новую эпоху; архив
  (сообщения, события, покупки, снимок карточки в эпохе) остаётся у владельца навсегда.
  Виджет ротирует только ключ сессии (visitorKey сохраняется); двухшаговый текст:
  «Забыть вас и начать с чистого листа?» → «Готово — начинаем с чистого листа».
  Текстовая просьба «забудь всё» в чате перехватывается сервером без LLM и делает то же
  самое. Операция идемпотентна и не требует авторизации (ключ и есть его идентификатор).
  В админке у карточки — таблица эпох: галочка включает/выключает эпоху («вернуть в активную» —
  снимок в пустые поля карточки, старая переписка снова видна модели, событие `memory_restored`;
  «скрыть обратно» — маркер возвращается, карточку не чистит, событие `memory_hidden`). Двойной клик
  по строке раскрывает снимок таблицей полей — выбранные поля возвращаются точечно
  (`{resetId, fields}` → событие `memory_fields_restored`). Админка прямоугольная, темы светлая/тёмная.

## 11. Виджет-чат: возможности (`app/chat-core.tsx`)

- Рендерится в двух местах: страница `/` (обычный режим) и `/embed/<key>` (compact,
  внутри iframe).
- Стриминг ответа через `useChat` + `DefaultChatTransport`; «Ищу в базе знаний…» — пока
  ждём; цитаты-чипы `[n]`; 👍/👎 с защитой от повторного голоса (восстановленные оценки
  показываются как уже поставленные).
- Пометка «Бот написал сам» у проактивных касаний; касания остаются в ленте навсегда.
- «Забыть меня»; кнопка «▾» (свернуть, в embed); перетаскивание окна за шапку (в embed);
  на мобильных (<480px) окно открывается на весь экран.
- Палитра: акцент, тёмная тема, точечные цвета, шрифты — всё из `theme` (см. §7 и
  `lib/widget-theme.ts`; все значения нормализуются и клампятся при сохранении).
- Ошибка рендера не оставляет пустоту: `ChatBoundary` показывает «Обновите страницу».

## 12. Админка

Вход: `/admin` → пароль `ADMIN_SECRET`. Сессия — httpOnly cookie с HMAC-токеном
(stateless; сравнения — `timingSafeEqual`). Панели по выбранному боту:

1. **BotBar** — выбор бота, создание нового («+ Новый бот»).
2. **StatsPanel** — «Статистика за 7 дней»: диалоги, ответы, 👍/👎, средняя латентность,
   токены, оценка стоимости.
3. **BotSettings** — три вкладки:
   - **Интерфейс**: позиция/размер/подпись кнопки, цвета (пикеры + сброс), иконка и аватар
     (файл ≤100 КБ → data-URL или ссылка), заголовок/подзаголовок, отступы, тень, анимация,
     прозрачность (ползунок), размеры окна, закругление, тёмная тема, тонкая настройка
     8 цветов, шрифты (CSS-family + ссылка на веб-шрифт), проактивный тизер
     (включён/задержка 3–60 с/текст ≤160), кнопка «Открыть виджет и проверить оформление».
   - **Логика**: всё про поведение и личность (см. §8.3) + системный промпт.
   - **Каналы**: сниппет вставки (`loader.js?v=14`), список «Сайты для встраивания»
     (origin-allowlist; пусто = разрешено везде), карточки будущих каналов (Telegram,
     WhatsApp Business, VK, API).
4. **DocumentsPanel** («База знаний») — загрузка txt/md/pdf ≤4 МБ, статусы
   (ожидает/обработка/готов/ошибка), авто-продолжение для больших файлов, «повторить»
   для ошибок и зависших, удаление.
5. **VisitorsPanel** («Посетители») — список карточек (поиск, число диалогов, контакты),
   карточка: правка имени/контактов/тегов/заметок/DND, память бота (дайджест, интересы),
   список бесед (дата, стадия, исход, касания, сообщений), лента событий. Если миграция
   0003 не применена — панель показывает подсказку, что запустить.

| `npm run smoke:admin` | Вход в админку, загрузка тестового документа → проверка ответа по нему → round-trip настроек (с возвратом) → удаление документа |
| `npm run smoke:embed` | `loader.js`, `/embed/<key>`, `/api/bot?key=` c origin-allowlist (временный + откат), тема (round-trip с откатом), `/api/feedback`, квота |
| `npm run smoke:memory` | Диалог 20+ сообщений: имя из первого сообщения вспоминается «пустым» клиентом после перезагрузки (память серверная); временно расширяет память и возвращает как было |
| `npm run smoke:visitor` | Карточка посетителя: извлечение имени/телефона, привязка беседы, события, админ-API (список/правка/детали), «забыть меня» (новая эпоха, память не удаляется), структурированные факты (sql/0006) |
| `npm run smoke:nudge` | Дожим: пауза → касание → запись в беседу → интервал → сброс ответом → DND → реактивация `lost` → стоп-слова → тихие часы |
| `npm run smoke:reset` | Память-эпохи: «забыть меня» (кнопка и текст) не удаляет данные, активная память обнулена, эпохи в `memory_resets`, лента новой эпохи пуста, возврат оживляет беседу |
| `npx tsx scripts/smoke-local.ts` | Без сети/ключей: чанкер, vector-literal, env guard, ключи session/visitor, санитайз/слияние/дедупликация фактов, стоп-слова, тихие часы, парсинг настроек, шкалы характера |
| `npm run eval` | Golden set (`evals/demo-shop.json`, 11 кейсов): факты, цитаты источников, честные отказы. Проверка фактов — нормализованным сравнением, отказов — регэкспами |
| `scripts/check.mjs`, `scripts/inspect-ai.mjs` | Dev-утилиты: проверка поверхности AI SDK в установленной версии и печать фактических сигнатур API из `.d.ts` (без сети) |

Смоуки умеют бить и в прод: `set SMOKE_BASE_URL=https://sitebot-nu.vercel.app` (или
`--env-file`, как в ручных прогонах). Многие из них на время теста правят настройки/темы —
всегда с восстановлением исходных значений.

**CI:** `.github/workflows/ci.yml` — на каждый push/PR: `npm ci` → `npm run build`
(typecheck + сборка) → локальный смоук. Ручной workflow `eval-prod.yml` запускает
golden set против прода (workflow_dispatch).

## 14. Окружение, деплой, эксплуатация

**Переменные окружения** (`.env.local` локально, Vercel → Environment Variables в проде):

- `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` (принимается и новый `SUPABASE_SECRET_KEY`);

- `ADMIN_SECRET` — пароль админки.

Все читаются **лениво в рантайме** — сборка без env проходит.

**Деплой:** push в `main` (CI) + `npx vercel deploy --prod --yes`; алиас
`sitebot-nu.vercel.app` обновляется каждым деплоем. Миграции — вручную в Supabase SQL
Editor, по порядку (0001 → 0002 → 0003). Подробности — `DEPLOY.md`, `RUNBOOK.md`.

## 15. Принципы и договорённости (почему сделано именно так)

- **Сервер — единственный держатель ключей и логики.** Браузер не ходит в Supabase;
  «можно ли касание», «достигнута ли цель», «что в памяти» решает сервер. Клиент — лишь
  отображение и таймеры.
- **Память — серверная.** Виджет не переигрывает историю; контекст для модели строится из
  БД. Это делает память устойчивой к перезагрузкам, новым устройствам (в рамках того же
  браузера) и не раздувает HTML/трафик.
- **Деградация вместо падений.** Нет миграции 0002/0003, положили FTS, не записалась
  персистенция, упал стратег — чат всё равно отвечает. Везде, где возможно, стоит
  `isMissingColumnError`/`isMissingRelationError` и «best effort»-обёртки.
- **Стоимость под контролем.** Стратег и текст касания — дешёвая flash-модель, короткие
  ответы, лимиты касаний (≤5) и дневная квота (300 запросов/бот). Стоимость ответов
  оценивается по `lib/pricing.ts` и видна в статистике.
- **Гардрейлы вшиты в промпт, а не в надежду.** Каждая «агрессивная» шкала сопровождается
  запретами (не выдумывать, не давить после отказов, честность при хитрости); стоп-слово —
  мгновенный DND без LLM; «забыть меня» — новая эпоха памяти (архив остаётся у владельца).
- **UI-сигналы не должны раздражать.** У свёрнутого окна — только счётчик и пульсация,
  никаких всплывающих текстов; `page_hidden` троттлится; тизер закрывается один раз и
  больше не мешает.
- **Версии и кэш.** loader версионируется (`?v=14` в сниппетах), версия видна в консоли;
  кэш 5 минут + SWR — обновления доезжают быстро, но не мгновенно.

## 16. Известные ограничения и задел

- **Ф4 (метрики)** — сводка за 7 дней есть; конверсия/дожим-метрики (`nudge_answered /
  nudge_sent`, время до цели) — следующий шаг.
- **Ф5 (мессенджер)** — дожим вне сайта (Telegram → WhatsApp) не реализован; вкладка
  «Каналы» показывает статусы. Пока канал только один: сайт (виджет).
- **Касания живут на странице** — серверных крон-задач нет: пока сайт закрыт, «дожать»
  можно только при следующем визите/открытой вкладке.
- В `conversations` накапливаются тестовые беседы от смоуков (`e2e-*`, `memory-*`,
  `smoke-*`). Не мешает; при желании — разовая чистка или автоочистка в смоуках.
- Ответы бота на вопросы «хранишь ли ты историю разговоров» зависят от системного
  промпта бота — при желании добавить в промпт памяти явную фразу.
- `conversations.visitor` (jsonb из 0001) — унаследованное поле, не используется;
  память живёт в `visitors`.
