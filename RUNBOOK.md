# RUNBOOK — эксплуатация sitebot

## Что где

- Прод: https://sitebot-nu.vercel.app (алиас обновляется каждым деплоем) · админка: `/admin`.
- GitHub: https://github.com/UzunDemir/sitebot (ветка main) · Vercel-проект: demirs-projects-47f251dd/sitebot.
- Секреты: локально — `.env.local`; в проде — Vercel → Settings → Environment Variables
  (SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, DEEPSEEK_API_KEY, GOOGLE_GENERATIVE_AI_API_KEY, ADMIN_SECRET).
- Пароль админки = ADMIN_SECRET. Смена: обновить в `.env.local` и в Vercel (Type: Sensitive) → Redeploy.
- Админка: прямоугольный интерфейс, две темы — кнопка «🌙 Тёмная тема» / «☀️ Светлая тема» в шапке
  (выбор запоминается в браузере).
- Миграции SQL (Supabase → SQL Editor, по разу, по порядку): `sql/0001_init.sql`, `sql/0002_settings.sql`,
  `sql/0003_seller.sql` (карточки посетителей и события), `sql/0004_card.sql` (дата рождения, предпочтения,
  претензии, покупки), `sql/0005_memory_reset.sql` (эпохи «забывания» — память не удаляется),
  `sql/0006_visitor_facts.sql` (структурированные факты), `sql/0007_style.sql` (шкалы: CTA-бюджет,
  кулдаун после отказов). Без 0003–0007 приложение работает на дефолтах:
  панель «Посетители» показывает хинт, активное окно памяти отключается, факты не собираются,
  шкалы работают как промпт.

## Ежедневные операции

- Пополнить базу знаний: `/admin` → бот → «База знаний» → загрузить `.txt` / `.md` / `.pdf`.
  Большие PDF индексируются проходами («частями») — прогресс виден в списке, при обрыве — кнопка «повторить».
- Сменить модель / промпт / внешний вид виджета: карточка бота → «Сохранить».
- Проверить ответы: главная страница (переключатель ботов) или `/embed/<public_key>`.
- Карточки посетителей: карточка бота → «Посетители» (ниже «Базы знаний») — имя, дата рождения, контакты,
  теги, заметки, предпочтения, претензии, память бота, покупки, беседы и лента событий. Имя/контакты/ДР
  собираются автоматически после ответов (дешёвая модель); заметки, теги и покупки правятся вручную.
  «Забыть меня» (кнопка или просьба «забудь всё» в чате) не удаляет данные: открывается новая эпоха
  памяти — бот честно начинает с чистого листа, а архив (снимок карточки в эпохе, беседы, события,
  покупки) остаётся у владельца. Возврат посетителя оживляет беседу.
  В карточке — секция «Память: эпохи» (таблица): галочка включает/выключает эпоху (снятый маркер —
  старая переписка снова видна модели), двойной клик по строке раскрывает снимок таблицей полей —
  выбранные поля можно вернуть в карточку (заполняются только пустые поля, правки владельца не
  перезаписываются).
- Дожим: карточка бота → «Логика» → «Дожим молчащих посетителей» (касаний подряд, пауза перед первым,
  интервал, тихие часы). Бот пишет сам в рамках лимита; ответ посетителя сбрасывает серию; стоп-слово
  («не пишите мне больше») выключает дожим навсегда (DND в карточке посетителя). Потерянный диалог не
  глухо закрыт: серия продолжается (по лимиту касаний), а новое сообщение посетителя оживляет беседу.
  Касания остаются в ленте навсегда (до ответа — с пометкой «бот написал сам», после — как обычные
  сообщения); у свёрнутого окна на кнопке — счётчик непрочитанных и пульсация, без всплывающего текста.
  Свёрнутая вкладка дожим не блокирует — сообщение будет ждать в диалоге.
- Характер бота: «Логика» → ползунки «Агрессивность», «Тон», «Юмор», «Хитрость», «Остроумие», «Эмпатия»
  (0–100); влияют на системный промпт и тексты касаний.
- Знания и персона: «Логика» → «Знания и персона» — чекбоксы профессиональных наборов (продажи,
  возражения, психология, переговоры, сервис, юмор, актёрское мастерство, эксперт) и «свои знания»
  (до 2000 символов). Наборы задают приёмы и стиль; факты бот берёт только из базы знаний и диалога.
- Шкалы — реальная механика (sql/0007): негатив и отказ подавляют продажи; после 2 явных отказов —
  15-минутное «остывание» (без CTA и дожима); просьбы контакта — не больше 3 на беседу; при жалобе
  и эмпатии ≥70 ответ начинается с признания чувств; при негативе юмор выключается, «!!» и эмодзи
  вычищаются из ответа; остроумие/хитрость поднимают temperature. Пост-проверки пишут style_flags
  и корректируют следующий ответ. Требует sql/0007_style.sql; без неё — деградация до промпт-правил.
- Тактики (стратег 2.0): сервер выбирает тактику на ответ — «выбор из двух», «предвосхищение
  возражения», «вопрос-закрытие», «разрешение», «передача менеджеру», «сначала ценность» — по стадии,
  хитрости и агрессивности; ротация без повторов подряд. Выключены при негативе/отказе/кулдауне,
  цели «нет» и агрессивности ≤20. Вердикт стратега (тон, отказ) уточняет regex-детекторы и влияет
  на следующий ответ; событие `tactic_used`, `last_tactic` в беседе (колонки sql/0007).
- Пресеты характера в «Логике»: «Поддержка», «Продажа-консультация», «Активный клоузер» + авто-
  предупреждение при конфликте «агрессия ≥80 и эмпатия ≥80».
- Статистика (таб «Статистика»): диалоги/ответы/оценки/стоимость + таблица «Тактики» (ответов,
  бесед с целью, конверсия) и блок «Отказы / флаги стиля» — собирается из событий (tactic_used,
  refusal, style_flags, goal_reached) и работает даже до применения sql/0007.
- Виджет: пока бот думает — три бегущие точки («печатает»); настраиваются цвет («Тонкая настройка
  цветов» → «Точки «печатает»»), слово перед точками (по умолчанию «Печатает»; можно «writing»),
  анимация (прыжок или волна слева направо, как в Viber), размер, высота прыжка и скорость (блок
  «Индикатор «печатает»»), по умолчанию 5 px / 3 px / 900 мс. Ответ пишется прямо на месте точек (точки — внутри пузыря
  ассистента, первый токен заменяет их). Курсор автоматически в поле ввода: при открытии окна,
  после каждого ответа и по клику в ленте. Кнопка сворачивания в шапке — крупнее. Касания при
  ОТКРЫТОМ окне — красный кружок с числом поверх аватара (как бейдж свёрнутого окна): клик —
  переход к первому непрочитанному касанию, курсор в поле ввода, счётчик сброшен.
- Звук нового сообщения: включается в «Интерфейсе» → блок «Звук нового сообщения» (по умолчанию
  включён, есть «Прослушать»). Касания («бот написал сам») звучат всегда — даже при свёрнутом
  окне; обычный ответ — только если вкладка была неактивна. Браузеры включают звук после первого
  клика или нажатия на странице (ограничение автовоспроизведения). На мобильных звук играет
  верхняя страница (loader) после первого касания сайта — iOS Safari не наследует касание в
  iframe; виджет просит её через рукопожатие `sitebot:hello` → `sitebot:loader`.
  `navigator.audioSession='playback'` (iOS 16.4+) звучит и при бесшумном режиме. Если на сайте
  закеширован старый loader — виджет играет сам (как на десктопе).
- Лаунчер и касания: порог тапа для пальца 22 px (движение сильнее — перетаскивание, меньше —
  открытие чата); после тапа/драга синтетический click гасится 500 мс, совместимостные
  mouse-события после касания игнорируются. Раньше тап с лёгким смещением пальца не срабатывал —
  на телефоне виджет зачастую просто не открывался.
- Диагностика загрузчика: стадии (`loader_loaded`, `loader_tap`, `loader_drag`, `loader_open`,
  `loader_frame_ready`, `loader_error`, с UA и размером экрана) пишутся в события бота — на реальном
  устройстве видно, где обрывается цепочка открытия. `loader.js` отдаётся с `max-age=0,
  must-revalidate` — обновления подхватываются сразу.

## Лимиты

- Google free tier (эмбеддинги): жёсткие лимиты запросов; при упоре — понятная ошибка и «повторить».
  При регулярных больших загрузках — включить биллинг Google (Tier 1) или сменить провайдера эмбеддингов.
- Квота чата: 300 запросов/сутки на бота (константа в `app/api/chat/route.ts`), счётчик — `quota_counters`,
  расход виден в админке (карточка «Статистика»).
- Тело запроса Vercel ~4.5 МБ; текст одного документа ≤ 300k символов (`MAX_CONTENT_CHARS` в `lib/ingest.ts`).

## Проверки

- Смоуки (по умолчанию — против прода, создают и чистят тестовые данные):
  `npm run smoke:e2e` · `npm run smoke:admin` · `npm run smoke:embed`.
  Локально: поднять сервер и запустить те же команды без правок (по умолчанию бьют в localhost, если
  задать `SMOKE_BASE_URL` — в указанный адрес).
- Память диалога: `npm run smoke:memory` — длинный диалог (20+ сообщений): имя из первого сообщения
  вспоминается даже «пустым» клиентом (виджет не показывает прошлую переписку — контекст сервер собирает
  из БД); на время теста ставит «Память диалога» = 50 и возвращает как было.
- Карточка посетителя: `npm run smoke:visitor` — диалог с visitorKey → имя, телефон, дата рождения и
  предпочтения попадают в карточку, события пишутся, админ-API сохраняет заметки/ДР/предпочтения,
  покупки добавляются и удаляются, «забыть меня» открывает эпоху (карточка и архив остаются).
  Требует `sql/0003_seller.sql`, `sql/0004_card.sql` и `sql/0006_visitor_facts.sql` (проверяет и
  структурированные факты).
- Память-эпохи: `npm run smoke:reset` — кнопка «Забыть меня» и текстовая просьба «забудь всё»:
  карточка и сообщения/покупки/события сохранены (память не удаляется), активная память обнулена,
  эпохи в `memory_resets`, лента новой эпохи пуста, возврат оживляет беседу; админка — «вернуть в
  активную»/«скрыть обратно». Требует `sql/0005_memory_reset.sql`.
- Дожим: `npm run smoke:nudge` — пауза перед касанием, само касание (текст + запись в беседу), интервал,
  сброс после ответа, DND, реактивация потерянного диалога и его оживление, стоп-слова, тихие часы.
  Настройки возвращает как было.
- Оценки качества: `npm run eval` (набор `evals/demo-shop.json`; формат: q / expect / expectAny / source / refusal).
  Перед прогоном бот должен быть активен.
- CI: на каждый push — сборка и локальный смоук (`.github/workflows/ci.yml`);
  ручной прогон оценок — GitHub → Actions → «Prod eval» → Run workflow
  (адрес можно переопределить repository variable `EVAL_BASE_URL`).

## Деплой и откат

- Деплой: `npx vercel deploy --prod --yes` (или подключить git-автодеплой: `npx vercel git connect`).
- Откат: `npx vercel ls sitebot` → найти предыдущий деплой со статусом Ready → `npx vercel redeploy <url>`.
- Логи рантайма: `npx vercel logs https://sitebot-nu.vercel.app`.

## Частые проблемы

- У посетителей «Protected by Vercel Authentication» / 404: Settings → Deployment Protection →
  Vercel Authentication → Standard Protection. Хеш-URL конкретного деплоя закрыт — это норма.
- Документ завис в «обработка» (функция убита по таймауту 60 с): подождать 5+ минут → «повторить».
- Виджет не появляется на сайте-хосте: бот активен? домен в «Сайтах для встраивания»? в сниппете актуальный `data-bot`?
- Оценки/сообщения не пишутся: у посетителя может быть заблокирован localStorage (нет sessionKey → нет истории).
- Виджет не показывает прошлую переписку — так задумано: лента всегда начинается с приветствия
  (+ «с возвращением» для знакомых), а память для модели сервер собирает из беседы в БД
  (`historyDepth` сообщений, 0 = вся беседа). Проверка памяти: `npm run smoke:memory`.
- Карточек посетителей нет: примените `sql/0003_seller.sql`; панель «Посетители» сама показывает этот хинт.
  Карточка появляется после первого сообщения посетителя (извлечение фактов — фоном, ~3–5 с).
- Дожим молчит: серия касаний ограничена («касаний подряд») и стартует заново после ответа посетителя;
  `goal_reached` оживает при новом сообщении, `stopped` и DND — нет (только снять DND в карточке или новый
  диалог «Забыть меня»); проверьте «Проактивные касания», тихие часы по tz и `stage/outcome` в карточке.
- В карточке нет ДР/предпочтений/покупок: примените `sql/0004_card.sql`; без неё бот просто не собирает
  эти поля, остальное работает. Поля собираются после сообщений посетителя или вручную в панели.
- Бот не пишет первым: проверьте «Дожим» (включён, касаний > 0), тихие часы, DND у посетителя и окно
  молчания (пауза/интервал). Касание доставляется, пока страница с виджетом открыта — свёрнутая
  вкладка не мешает: сообщение будет ждать в диалоге.

## Безопасность (текущий уровень — демо)

- Supabase закрыт полностью (RLS без публичных политик), браузер ходит только в наши API.
- Origin-allowlist виджета — проверка по Referer: базовый барьер, не защита от подделки.
  Для клиентских внедрений стоит добавить подписанные домены/токены (следующая фаза).
- Админка — общий пароль; для прод-использования — полноценная аутентификация (Supabase Auth).
