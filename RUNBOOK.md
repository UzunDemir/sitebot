# RUNBOOK — эксплуатация sitebot

## Что где

- Прод: https://sitebot-nu.vercel.app (алиас обновляется каждым деплоем) · админка: `/admin`.
- GitHub: https://github.com/UzunDemir/sitebot (ветка main) · Vercel-проект: demirs-projects-47f251dd/sitebot.
- Секреты: локально — `.env.local`; в проде — Vercel → Settings → Environment Variables
  (SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, DEEPSEEK_API_KEY, GOOGLE_GENERATIVE_AI_API_KEY, ADMIN_SECRET).
- Пароль админки = ADMIN_SECRET. Смена: обновить в `.env.local` и в Vercel (Type: Sensitive) → Redeploy.
- Миграции SQL (Supabase → SQL Editor, по разу, по порядку): `sql/0001_init.sql`, `sql/0002_settings.sql`,
  `sql/0003_seller.sql` (карточки посетителей и события; без неё приложение работает на дефолтах).

## Ежедневные операции

- Пополнить базу знаний: `/admin` → бот → «База знаний» → загрузить `.txt` / `.md` / `.pdf`.
  Большие PDF индексируются проходами («частями») — прогресс виден в списке, при обрыве — кнопка «повторить».
- Сменить модель / промпт / внешний вид виджета: карточка бота → «Сохранить».
- Проверить ответы: главная страница (переключатель ботов) или `/embed/<public_key>`.
- Карточки посетителей: карточка бота → «Посетители» (ниже «Базы знаний») — имя, контакты, теги,
  заметки, память бота, беседы и лента событий. Имя/контакты собираются автоматически после ответов
  (дешёвая модель), заметки и теги правятся вручную. Посетитель может стереть себя кнопкой «Забыть меня».
- Дожим: карточка бота → «Логика» → «Дожим молчащих посетителей» (касаний подряд, пауза перед первым,
  интервал, тихие часы). Бот пишет сам в рамках лимита; ответ посетителя сбрасывает серию; стоп-слово
  («не пишите мне больше») выключает дожим навсегда (DND в карточке посетителя). Потерянный диалог не
  глухо закрыт: серия продолжается (по лимиту касаний), а новое сообщение посетителя оживляет беседу.
  Касания остаются в ленте до ответа; у свёрнутого окна на кнопке растёт счётчик непрочитанных.
  Свёрнутая вкладка дожим не блокирует — сообщение будет ждать в диалоге.
- Характер бота: «Логика» → ползунки «Агрессивность», «Тон», «Юмор», «Хитрость», «Остроумие» (0–100);
  влияют на системный промпт и тексты касаний.

## Лимиты

- Google free tier (эмбеддинги): жёсткие лимиты запросов; при упоре — понятная ошибка и «повторить».
  При регулярных больших загрузках — включить биллинг Google (Tier 1) или сменить провайдера эмбеддингов.
- Квота чата: 300 запросов/сутки на бота (константа в `app/api/chat/route.ts`), счётчик — `quota_counters`,
  расход виден в админке (карточка «Статистика»).
- Тело запроса Vercel ~4.5 МБ; текст одного документа ≤ 300k символов (`MAX_CONTENT_CHARS` в `lib/ingest.ts`).

## Проверки

- Смоуки (по умолчанию — против прода, создают и чистят тестовые данные):
  `npm run smoke:e2e` · `npm run smoke:admin` · `npm run smoke:embed`.
  Локально: поднять сервер и запустить те же команды без правок (по умолчанию бьют в localhost, если
  задать `SMOKE_BASE_URL` — в указанный адрес).
- Память диалога: `npm run smoke:memory` — длинный диалог (20+ сообщений): имя из первого сообщения
  должно вспомниться после «перезагрузки»; на время теста ставит «Память диалога» = 50 и возвращает как было.
- Карточка посетителя: `npm run smoke:visitor` — диалог с visitorKey → имя и телефон попадают в карточку,
  события пишутся, админ-API сохраняет заметки, «забыть меня» удаляет карточку и беседы. Требует `sql/0003_seller.sql`.
- Дожим: `npm run smoke:nudge` — пауза перед касанием, само касание (текст + запись в беседу), интервал,
  сброс после ответа, DND, реактивация потерянного диалога и его оживление, стоп-слова, тихие часы.
  Настройки возвращает как было.
- Оценки качества: `npm run eval` (набор `evals/demo-shop.json`; формат: q / expect / expectAny / source / refusal).
  Перед прогоном бот должен быть активен.
- CI: на каждый push — сборка и локальный смоук (`.github/workflows/ci.yml`);
  ручной прогон оценок — GitHub → Actions → «Prod eval» → Run workflow
  (адрес можно переопределить repository variable `EVAL_BASE_URL`).

## Деплой и откат

- Деплой: `npx vercel deploy --prod --yes` (или подключить git-автодеплой: `npx vercel git connect`).
- Откат: `npx vercel ls sitebot` → найти предыдущий деплой со статусом Ready → `npx vercel redeploy <url>`.
- Логи рантайма: `npx vercel logs https://sitebot-nu.vercel.app`.

## Частые проблемы

- У посетителей «Protected by Vercel Authentication» / 404: Settings → Deployment Protection →
  Vercel Authentication → Standard Protection. Хеш-URL конкретного деплоя закрыт — это норма.
- Документ завис в «обработка» (функция убита по таймауту 60 с): подождать 5+ минут → «повторить».
- Виджет не появляется на сайте-хосте: бот активен? домен в «Сайтах для встраивания»? в сниппете актуальный `data-bot`?
- Оценки/сообщения не пишутся: у посетителя может быть заблокирован localStorage (нет sessionKey → нет истории).
- Виджет «не помнит» диалог: у посетителя старый или очищенный localStorage; память включена при
  `historyDepth` > 0 (по умолчанию 40 сообщений, 0 = вся беседа); история подтягивается из `GET /api/chat/history`.
- Карточек посетителей нет: примените `sql/0003_seller.sql`; панель «Посетители» сама показывает этот хинт.
  Карточка появляется после первого сообщения посетителя (извлечение фактов — фоном, ~3–5 с).
- Бот не пишет первым: проверьте «Дожим» (включён, касаний > 0), тихие часы, DND у посетителя и окно
  молчания (пауза/интервал). Касание доставляется, пока страница с виджетом открыта — свёрнутая
  вкладка не мешает: сообщение будет ждать в диалоге.

## Безопасность (текущий уровень — демо)

- Supabase закрыт полностью (RLS без публичных политик), браузер ходит только в наши API.
- Origin-allowlist виджета — проверка по Referer: базовый барьер, не защита от подделки.
  Для клиентских внедрений стоит добавить подписанные домены/токены (следующая фаза).
- Админка — общий пароль; для прод-использования — полноценная аутентификация (Supabase Auth).
